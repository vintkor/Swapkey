# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Swapkey: a macOS menu-bar app (Swift, AppKit, no Xcode project) in the style of Punto Switcher. It watches typing globally, detects words typed in the wrong keyboard layout, and shows a floating panel with suggestions. `⌘N` picks one, where N is the layout's position among the enabled layouts in System Settings (so each layout always has the same key): it switches the input source and retypes the fragment.

## Commands

- `swift build`: debug build, for compile checks only.
- `./build.sh` (or `./build.sh debug`): builds and assembles `build/Swapkey.app` (Info.plist with `LSUIElement`, codesign). Signs with the self-signed "Punto Dev" code-signing certificate from the login keychain (it shows as `CSSMERR_TP_NOT_TRUSTED`, which codesign tolerates), falling back to ad-hoc if it is missing. Version = latest `vX.Y.Z` git tag (`v0.0.0` without one), build number = `git rev-list --count HEAD`; shown at the bottom of the status menu.
- `swift scripts/make-icon.swift`: redraws `Resources/AppIcon.icns` (gradient squircle + SF Symbol `keyboard`); the generated file is committed and copied by `build.sh`.
- `open build/Swapkey.app`: run it. The app needs **Accessibility** permission (`open "x-apple.systempreferences:com.apple.preference.security?Privacy_Accessibility"`). TCC ties it to the designated requirement: with "Punto Dev" that is identifier + certificate, stable across rebuilds; with ad-hoc it is the cdhash, so the permission has to be removed and granted again after every rebuild.
- `./test.sh`: runs the tests (Swift Testing; XCTest is not in Command Line Tools, and Swift Testing needs explicit framework paths there, which the script passes). `RulesTests` cover the text rules; `CorpusTests` type every line of `Tests/SwapkeyTests/Corpus/{ru,uk,en}.txt` word by word (`Session` in `Support.swift` mirrors `SwitchController`) and check that correct text gets no layout offers and that text typed in the wrong layout comes back exactly after a pick. They print a report; run them after any change to detection or conversion. Layouts come from all installed ones (`TISCreateInputSourceList(…, true)`), not only the enabled ones.

## Architecture

Data flow: `KeyboardMonitor` (CGEventTap) → `SwitchController` (buffer of `KeyStroke`s) → `BufferAnalyzer` + `LayoutDetector` (on each space) → `SuggestionPanel` → on hotkey `InputSources.select` + `Injector.replace`.

`BufferAnalyzer` holds every decision about the buffer (verdicts, what to offer, automatic rewrites, what a pick types) as functions of a stroke array, with no UI or side effects besides caches; `SwitchController` keeps the state, the panel, timers and events. New logic about text belongs in `BufferAnalyzer`, so the tests can reach it.

Key ideas that span files:

- **Physical keys, not characters.** The buffer stores key code + shift/caps (`KeyStroke`). `KeyboardLayout.text(for:)` re-renders the same strokes through any layout via `UCKeyTranslate`, so one buffer serves every enabled layout.
- **Detection = system spell checker.** `LayoutDetector` uses `NSSpellChecker` with the layout's primary TIS language (`kTISPropertyInputSourceLanguages.first`). The word is "wrong" if it is invalid in the current layout and valid in another one. Candidates whose text matches the current layout's (e.g. Russian vs Ukrainian for shared letters) are skipped. Layouts without a system dictionary are ignored. The system Russian dictionary has big gaps ("раскладка", "репозиторий", "кейсы"), and with one letter changed such a word is often valid Ukrainian ("кейсы" → "кейсі"); `BufferAnalyzer.isTrusted` drops a candidate whose text shares at least half its letters with the typed one when one of the 5 previous words is valid in the current language only.
- **Spelling.** `LayoutDetector.spellingFix` returns the spell checker's `correction` (or first guess). A word valid nowhere opens the panel either as a typo in the current language (spelling row, `⌘0`, fixes only `.unknown` finished words) or, if only another layout has a fix, as a layout candidate (the fix is only evidence: layout rows show the plain conversion).
- **Learning words.** When the panel goes away without a pick (timeout, correct-word streak, Esc, Return), `learnableWords` (flagged only for lack of a dictionary entry: a current-language spelling fix or a sibling-layout candidate, never wrong-layout gibberish) get a mark in `Settings.ignoredWords`; at `Settings.learnAfterIgnores` the word goes to the system dictionary via `NSSpellChecker.learnWord` (shared with all apps and languages) and to `Settings.learnedWords`, which the menu lists for removal (`unlearnWord`). The trailing unfinished word is never spell-fixed. Fixes are suggestions only: the system's best guess is often wrong (e.g. "превет" → "прервет").
- **Automatic rewrites.** Two, applied together by `SwitchController.autoFix` as one retype from the first changed stroke. Sticky Shift: after a word, "ПРивет" → "Привет" (`SwitchController.stickyShiftIndex`: two capitals then ≥2 lowercase letters; applied only if the result is a dictionary word, never with Caps Lock). It edits the buffer stroke too, so the buffer keeps matching the screen. Automatic rewrites must wait until `_pendingKeys` (keys the tap already passed to the app but `keyDown` has not processed) is 0, otherwise the delete count misses those keys; `analyzeWord` re-enqueues itself until then. Sentence capitalization (`capitalizeSentence`): a lowercase word after a token ending with `.`/`!`/`?` gets Shift on its first letter; `endsSentence` skips `...`, numbers, single letters, tokens with an inner dot ("т.е.") and a list of abbreviations; skipped if the previous token is a wrong-layout word (its "." is a letter there) or the sentence end is not in the buffer. Never lowercases after a comma: the system dictionary accepts lowercase names ("иван", "john"), so that would break "Привет, Иван". A `.`/`!`/`?` typed in the middle of text (`capitalizeAhead`) reads the text around the caret via AX (`CaretLocator.surroundingText`, retried until the app has inserted the mark) and fixes the next word with `Injector.replaceAhead`: → over the spaces, Forward Delete, the capital, ← back. It is the only edit past the caret; it does not touch the buffer, since the text before the caret stays the same.
- **Buffer validity.** `SwitchController` resets the buffer on anything that may move the caret or change text unseen (mouse clicks, arrows, Return/Tab/Esc, ⌘/⌃/⌥ combos, input source change). `keyDown` compares the TIS input source on every key (`syncCurrentLayout`): the change notification can arrive after the first keys of the new layout. While the panel is up, Backspace does not drop strokes but counts them in `erased`, so a pick still types the whole corrected phrase (it deletes only what is left on screen, and restores correct text erased before `anchor`); any printable key drops the erased strokes. On selection it deletes the visible characters from `anchor` and retypes the fragment from the first wrong word (`anchor`): words valid in the current layout stay as typed, every other word is re-rendered in the chosen layout (`BufferAnalyzer.correction`). The anchor also takes in words right before the first wrong one (`fragmentStart`): one-letter words ("F ntcns" → "А тесты"; not real ones of the current language, a hand-made list since the spell checker accepts any letter) and ambiguous ones. Ambiguous = valid as typed and valid once converted ("Lf" ↔ "Да", "шею" ↔ "it.": dictionaries accept lots of short abbreviations); in a layout row such a word is converted when a neighbouring word is (`hasConvertedNeighbour`). Words valid nowhere are converted without a spelling fix ("коммит" must not become "кормит"), unless they look like a typo in the current language. Punctuation is converted by key ("Ghbdtn? rfr" → "Привет, как", "ghbdtn/" → "привет."), except "?"/"!" ending the text ("tcnm?" → "есть?"). The panel shows exactly that text and updates on every key; it hides after `hideAfterCorrectWords` correct words in a row. The input source is switched only if the fragment ends with a corrected word.
- **Threading.** The event tap runs on its own thread (`swapkey.eventtap`): an active tap holds every key press and click in the system until the callback returns, so a busy main thread must never be in that path (it froze the whole machine once). The callback only decides whether to swallow a `⌘digit` (via the locked `hotkeyDigits`) and forwards everything else to main with `DispatchQueue.main.async`; never call `main.sync` from it. All other `SwitchController` state lives on main. Async work is guarded by `generation` (bumped on reset). `CaretLocator` runs on a background queue with a global AX timeout of 0.25 s. Synthetic events are posted from the `Injector` queue.
- **Permission revocation.** An active tap that outlives its Accessibility permission freezes keyboard and mouse system-wide until reboot (this happened when Swapkey was removed from the Accessibility list while running). `AppDelegate` polls `AXIsProcessTrusted()` every 0.5 s and calls `KeyboardMonitor.stop()` when it turns false; the tap is re-enabled after `tapDisabledBy*` only while trusted. `build.sh` kills a running Swapkey before replacing the bundle. Never remove Swapkey from the Accessibility list while it is running.
- **Own events.** `Injector` tags events with `eventSourceUserData = Injector.marker`, and `KeyboardMonitor` lets them through untouched. Events use `CGEventSource(.privateState)` + `flags = []` so the still-held ⌘ of the hotkey does not turn Backspace into "delete to line start".
- Panel position comes from `CaretLocator`, which tries several sources in order: caret AX bounds → neighbouring character bounds → focused element frame → focused window → mouse. It sets `AXManualAccessibility` on the frontmost app, because Electron/Chromium apps expose no caret otherwise. The source it picked is written to the system log (`log stream --predicate 'process == "Swapkey"'`).

User settings live in `Settings` (UserDefaults, `defaults read local.swapkey`): spelling on/off, sticky Shift fix, sentence capitalization, word learning (with the ignore counts and learned words), panel timeout (0 = never), correct words before hiding, switched-off layouts, excluded apps. They are edited from the status menu, which `AppDelegate` rebuilds on every open (`menuNeedsUpdate`); after a change call `SwitchController.settingsChanged()`. "Launch at login" uses `SMAppService.mainApp`, no stored flag. Switched-off layouts keep their hotkey digit (digits come from all enabled layouts). Other tunables (hotkey modifier, minimum word length) are static constants in `SwitchController` and `LayoutDetector`.
