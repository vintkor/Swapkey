# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Swapkey: a macOS menu-bar app (Swift, AppKit, no Xcode project) in the style of Punto Switcher. It watches typing globally, detects words typed in the wrong keyboard layout, and shows a floating panel with suggestions. `⌥N` picks one, where N is the layout's position among the enabled layouts in System Settings (so each layout always has the same key): it switches the input source and retypes the fragment.

## Commands

- `swift build`: debug build, for compile checks only.
- `./build.sh` (or `./build.sh debug`): builds and assembles `build/Swapkey.app` (Info.plist with `LSUIElement`, codesign). Signs with the self-signed "Punto Dev" code-signing certificate from the login keychain (it shows as `CSSMERR_TP_NOT_TRUSTED`, which codesign tolerates), falling back to ad-hoc if it is missing.
- `swift scripts/make-icon.swift`: redraws `Resources/AppIcon.icns` (gradient squircle + SF Symbol `keyboard`); the generated file is committed and copied by `build.sh`.
- `open build/Swapkey.app`: run it. The app needs **Accessibility** permission (`open "x-apple.systempreferences:com.apple.preference.security?Privacy_Accessibility"`). TCC ties it to the designated requirement: with "Punto Dev" that is identifier + certificate, stable across rebuilds; with ad-hoc it is the cdhash, so the permission has to be removed and granted again after every rebuild.
- Only Command Line Tools are installed (no Xcode), so XCTest may be unavailable. There is no test target. To check detection logic, compile `KeyboardLayout.swift` + `LayoutDetector.swift` together with a scratch `main.swift` via `swiftc` and call `LayoutDetector.analyze` directly.

## Architecture

Data flow: `KeyboardMonitor` (CGEventTap) → `SwitchController` (buffer of `KeyStroke`s) → `LayoutDetector` (on each space) → `SuggestionPanel` → on hotkey `InputSources.select` + `Injector.replace`.

Key ideas that span files:

- **Physical keys, not characters.** The buffer stores key code + shift/caps (`KeyStroke`). `KeyboardLayout.text(for:)` re-renders the same strokes through any layout via `UCKeyTranslate`, so one buffer serves every enabled layout.
- **Detection = system spell checker.** `LayoutDetector` uses `NSSpellChecker` with the layout's primary TIS language (`kTISPropertyInputSourceLanguages.first`). The word is "wrong" if it is invalid in the current layout and valid in another one. Candidates whose text matches the current layout's (e.g. Russian vs Ukrainian for shared letters) are skipped. Layouts without a system dictionary are ignored.
- **Spelling.** `LayoutDetector.spellingFix` returns the spell checker's `correction` (or first guess). A word valid nowhere opens the panel either as a typo in the current language (spelling row, `⌥0`, fixes only `.unknown` finished words) or, if only another layout has a fix, as a layout candidate (layout rows spell-fix converted words; a current-language typo stays as typed there). The trailing unfinished word is never spell-fixed. Fixes are suggestions only: the system's best guess is often wrong (e.g. "превет" → "прервет").
- **Sticky Shift.** The only automatic rewrite: after a word, "ПРивет" → "Привет" (`SwitchController.stickyShiftIndex`: two capitals then ≥2 lowercase letters; applied only if the result is a dictionary word, never with Caps Lock). It edits the buffer stroke too, so the buffer keeps matching the screen. Automatic rewrites must wait until `_pendingKeys` (keys the tap already passed to the app but `keyDown` has not processed) is 0, otherwise the delete count misses those keys; `analyzeWord` re-enqueues itself until then.
- **Buffer validity.** `SwitchController` resets the buffer on anything that may move the caret or change text unseen (mouse clicks, arrows, Return/Tab/Esc, ⌘/⌃/⌥ combos, input source change). While the panel is up, Backspace does not drop strokes but counts them in `erased`, so a pick still types the whole corrected phrase (it deletes only what is left on screen, and restores correct text erased before `anchor`); any printable key drops the erased strokes. On selection it deletes the visible characters from `anchor` and retypes the fragment from the first wrong word (`anchor`): words valid in the current layout stay as typed, every other word is re-rendered in the chosen layout (`SwitchController.correction`). The panel shows exactly that text and updates on every key; it hides after `hideAfterCorrectWords` correct words in a row. The input source is switched only if the fragment ends with a corrected word.
- **Threading.** The event tap runs on its own thread (`swapkey.eventtap`): an active tap holds every key press and click in the system until the callback returns, so a busy main thread must never be in that path (it froze the whole machine once). The callback only decides whether to swallow a `⌥digit` (via the locked `hotkeyDigits`) and forwards everything else to main with `DispatchQueue.main.async`; never call `main.sync` from it. All other `SwitchController` state lives on main. Async work is guarded by `generation` (bumped on reset). `CaretLocator` runs on a background queue with a global AX timeout of 0.25 s. Synthetic events are posted from the `Injector` queue.
- **Permission revocation.** An active tap that outlives its Accessibility permission freezes keyboard and mouse system-wide until reboot (this happened when Swapkey was removed from the Accessibility list while running). `AppDelegate` polls `AXIsProcessTrusted()` every 0.5 s and calls `KeyboardMonitor.stop()` when it turns false; the tap is re-enabled after `tapDisabledBy*` only while trusted. `build.sh` kills a running Swapkey before replacing the bundle. Never remove Swapkey from the Accessibility list while it is running.
- **Own events.** `Injector` tags events with `eventSourceUserData = Injector.marker`, and `KeyboardMonitor` lets them through untouched. Events use `CGEventSource(.privateState)` + `flags = []` so the still-held ⌥ does not turn Backspace into "delete word".
- Panel position comes from `CaretLocator`, which tries several sources in order: caret AX bounds → neighbouring character bounds → focused element frame → focused window → mouse. It sets `AXManualAccessibility` on the frontmost app, because Electron/Chromium apps expose no caret otherwise. The source it picked is written to the system log (`log stream --predicate 'process == "Swapkey"'`).

User settings live in `Settings` (UserDefaults, `defaults read local.swapkey`): spelling on/off, sticky Shift fix, panel timeout, correct words before hiding, switched-off layouts, excluded apps. They are edited from the status menu, which `AppDelegate` rebuilds on every open (`menuNeedsUpdate`); after a change call `SwitchController.settingsChanged()`. "Launch at login" uses `SMAppService.mainApp`, no stored flag. Switched-off layouts keep their hotkey digit (digits come from all enabled layouts). Other tunables (hotkey modifier, minimum word length) are static constants in `SwitchController` and `LayoutDetector`.
